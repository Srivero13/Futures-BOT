# Futures-BOT v0.2

**Research and simulation release. Does not send real orders.**

This document preserves the v0.2 scope. The repository is named Futures-BOT, but this version investigates spot only, without leverage. Futures support is pending.

Read `research/RESULTS.md` and `research/ANALYSIS.md` first: costs eliminate the benefit of the studied strategies. This version has no trained AI or demonstrated profitability.

## Changes

- Causal Decimal backtester using official BTC/ETH data, inventory liquidation, and costs on both sides.
- January 2025 selection, February validation, and March evaluation; cost scenarios and passive references.
- Net PnL, fees, drawdown, win rate, profit factor, worst/best hour, and hourly/per-second averages.
- Historical-engine controls: notional, minimum size/rounding, cooldown, daily entries, daily loss, and drawdown.
- Two-process laboratory: preserves recent samples on restart, rejects Binance queries delayed over five seconds, and adds realized/unrealized reporting.
- Code, official normalized data, hashes, tests, and results included for offline reproduction.

## Requirements

Ubuntu 24.04 LTS recommended; Python 3.10+ and an SSD. The v0.2 scripts need no pip packages or external libraries.
On Windows, replace `python3` with `py -3`; Windows was not tested for this release.

Clone the repository and enter the project directory:

```bash
git clone -b develop https://github.com/Srivero13/Futures-BOT.git
cd Futures-BOT
```

Do not overwrite v0.1 databases. Research data live in `datasets`; virtual accounts are created in `data`.

```bash
python3 restore_data.py
python3 -m unittest discover -s tests -v
python3 benchmark.py
python3 make_report.py
```

The benchmark takes minutes depending on hardware. Precomputed results can be read without running anything. Downloading is optional:

```bash
python3 download_data.py
```

Network failures do not trigger synthetic replacements. Files are checked against Binance's published checksums. Spot archive timestamps from 2025 are normalized from microseconds to seconds.

## Two independent bots

```bash
python3 bot.py run --config configs/two-paper.json --ticks 60
```

This uses synthetic data only, useful for testing processes and restarts. Alternatively, use public Binance quotes with local virtual trades:

```bash
python3 bot.py run --config configs/binance-paper.json --ticks 60
python3 paper_report.py data/binance-paper-a.sqlite3 --initial-capital 1000
```

`bot.py` is the inherited concurrent laboratory. Its strategy uses samples, NOT the backtester's candle model, and retains float accounting. Historical results from the new backtester do not predict this command's results. It does not connect two real accounts; it maintains two independent virtual ledgers.

Each ID has its own SQLite database and lock. Omitting `--ticks` runs until Ctrl+C. Creating a `PAUSE` file in the directory stops processes on their next iteration without liquidating positions. Removing it permits restarting. Loss halts persist. Reporting requires the correct initial capital from the configuration.

## Custom backtest and electricity

```bash
python3 backtest.py datasets/BTCUSDT-5m-2025Q1.csv --output results/custom --fee-bps 10 --overhead-hour 0.01
```

`0.01` is an EXAMPLE hourly expense in quote currency; replace it with your measured, converted cost. Benchmark fees are assumptions; your private account was not queried. The custom backtest defaults to SMA5/20 over the entire CSV; it is not the selection protocol used by `benchmark.py`.

## Capital.com demo

Only session and account-count checks are retained. In Bash:

```bash
read -r -s -p 'API key: ' CAPITAL_API_KEY
export CAPITAL_API_KEY
read -r -p 'Identifier: ' CAPITAL_IDENTIFIER
export CAPITAL_IDENTIFIER
read -r -s -p 'API password: ' CAPITAL_API_PASSWORD
export CAPITAL_API_PASSWORD
python3 bot.py capital-probe
unset CAPITAL_API_KEY CAPITAL_IDENTIFIER CAPITAL_API_PASSWORD
```

Generate the key on the official Capital.com website under Settings > API integrations, with 2FA. Use the API key password. Do not share secrets. The probe uses only the demo host. Actual authentication was not verified in this release.

## Pending scope in v0.2

No trained AI, testnet/demo execution, WebSocket, historical/online engine equivalence, broker reconciliation, complete filters, or global limits. Forex, CFDs, margin, and futures are not simulated. No official Hapi connector has been identified. Remain in simulation until there is a validated strategy and robust execution; this is not a finished real-investment product.

## Bundled data

Complete historical and result CSVs are compressed and split in `data_bundle/` for transfer. Run `python3 restore_data.py` once after cloning. It verifies SHA-256 and reconstructs the same CSVs without internet or overwriting different local files. JSON summaries and reports can be read directly.
