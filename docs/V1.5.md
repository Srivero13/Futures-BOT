# Version 1.5: CPU inference and datasets larger than RAM

Version 1.5 keeps a six-feature float64 Ridge model and Decimal paper accounting. More observations can change fitted coefficients and uncertainty estimates; they do not make inference faster by themselves. Speed comes from batched numerical work and avoiding repeated forecasts between closed candles. No GPU is required, and this release does not introduce live futures execution.

## Install and update

On an Ubuntu 24.04 host meeting the [system requirements](REQUIREMENTS.md), stop an existing coordinator before updating, then run inside your existing checkout:

```bash
git pull --ff-only origin develop
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

For optional compiled CPU batch inference:

```bash
python -m pip install -r requirements-fast.txt
python benchmark_v15.py --compiled --output data/benchmark-v15-local.json
```

The optional environment pins Numba 0.63.1 and restricts NumPy below 2.4. Base NumPy inference and live forecast caching work without Numba. The first compiled call includes compilation or cache loading; the benchmark reports it separately. No GPU purchase or model conversion is needed.

## Acquire multiple sources

Binance monthly archives are verified against published SHA256 checksums. Coinbase uses public historical candle pages with at most 299 requested minutes, half-open range filtering, sorted timestamps, bounded retries, and conservative request spacing. Both write canonical daily/monthly CSV shards and JSON provenance. Missing minutes are recorded, never fabricated. Historical Coinbase intervals may be absent when there were no ticks. See the official [Binance archive documentation](https://github.com/binance/binance-public-data) and [Coinbase candle specification](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-candles).

```bash
python download_v15_data.py --source binance --symbol BTCUSDT \
  --start 2024-01-01 --end 2025-11-01 --root data/market
python download_v15_data.py --source coinbase --symbol BTC-USD \
  --start 2025-10-01 --end 2025-11-01 --root data/market
```

Repeat with ETHUSDT and ETH-USD for Ethereum. The Binance range must begin and end on the first of a month. Dates are UTC; the end is exclusive. Re-running verifies and skips completed shards. Corrupted checkpoints fail explicitly. One downloader may own a root at a time; temporary downloads are removed on failure. The downloader retains a 1 GiB free-space reserve, but provision considerably more space for your OS and other applications.

New Binance and Coinbase endpoint requests timed out in the release workspace. The downloader parsing, integrity, and range handling were tested with fixtures; a successful fresh multi-source acquisition was **not** demonstrated in this release. The following commands describe a reproducible experiment once those endpoints are reachable, not a completed experiment.

## Train chronologically without loading all data

```bash
python train_v15.py --venue binance --symbol BTCUSDT \
  --files data/market/binance-BTCUSDT-*.csv \
  --train-end 2025-10-15 --calibration-end 2025-10-22 --test-end 2025-11-01 \
  --chunk-size 8192 --compiled --output data/research-v15
python train_v15.py --venue coinbase --symbol BTC-USD \
  --files data/market/coinbase-BTC-USD-*.csv \
  --train-end 2025-10-15 --calibration-end 2025-10-22 --test-end 2025-11-01 \
  --chunk-size 8192 --compiled --output data/research-v15
```

Omit `--compiled` if you installed only the base requirements. Use chronological, non-overlapping files for one venue, symbol, and one-minute timeframe per invocation. Shard metadata must match. Local canonical CSV/CSV.gz imports are supported with columns `timestamp,open,high,low,close,volume`; timestamps are UTC seconds and prices are decimal strings. For imports without sidecar metadata, the operator supplies venue identity; the report identifies this weaker provenance explicitly. A local checksum proves file integrity, not market-data authenticity.

Separate venue models prevent accidental USD/USDT label mixing. Coinbase models are research artifacts; they are not a Coinbase trading connector. No pooled multi-venue model, FX conversion, or cross-exchange arbitrage engine is claimed.

The reader holds one chunk plus a 24-candle overlap for a three-bar horizon. Gaps reset the feature/label window. Targets run from the next open to the open three minutes later; labels crossing a split are purged. Features use only closed candles. Train-only streaming moments provide scaling; a second pass reduces augmented least squares using QR, then solves a small system via SVD. This avoids a numerically fragile normal-equation inverse. Results are tested against an in-memory augmented SVD fit.

Calibration uses non-overlapping labels on a fixed UTC grid. A deterministic random-priority reservoir retains up to 100,000 errors. The 90th-percentile overprediction buffer is exact for the retained full set below that limit, approximate beyond it. It is not a guarantee of future coverage under changing markets. Holdout reporting includes rejected out-of-distribution rows, comparable zero-forecast RMSE, and cost-gate candidates. It is a forecast evaluation, not a fill simulator or a P&L backtest.

## Planning for 30+ GB

The pipeline scans CSV/gzip files in bounded chunks, including fitting, calibration, and holdout diagnostics. It performs four data passes plus integrity hashes, so SSD throughput and parsing matter. There is no 30 GB dataset-size ceiling in the algorithm; no 30+ GB run was performed here. The release used 44,108,369 bytes of existing canonical data and roughly 36 MiB peak process RSS per training run. That is evidence at the tested size, not a measured memory guarantee at 30 GB.

Use `--root /path/on/ssd/market` for downloads and point `--files` there. Use the memory and SSD planning budgets in the requirements guide, including room for download staging, OS, logs, backups, and future data. Keep raw data out of Git; only code, hashes, small models, and research reports belong in the repository. Do not add duplicate candles or padding to reach a size target. Additional years, instruments, and venues should answer a specific validation question.

## Live timing and model promotion

Forecasts are cached only until a new closed candle or a feed/clock reset. Quote costs and all existing freshness, pause, position, exposure, drawdown, and exit checks still run at the established measured cadence. Inference microseconds are not order round-trip milliseconds. This release does not reduce timing gates on the basis of a CPU benchmark. Run the existing local latency profiler on the actual runtime host to measure its actual connection.

New research models are saved with `approved: false` outside the active `models/` directory by default. Existing active model files are unchanged. No profitability was established; larger training sets did not beat the zero-return forecast in this retrospective run. Do not promote these release research artifacts as evidence of a trading edge.
